# Lane `consumer2`: Milestone 1 fix, generated ConfigMap data in the consumer graph (Opus)

Branch `p6di/consumer2`, worktree `.claude/worktrees/p6di-consumer2`. Ledger D-0005. Read `_common.md` first, then
`PLAN-M1.md`, `M1-IMPLEMENTATION.md` and `status/consumer.md` (the previous lane's work, merged at 3634f501).

## The defect (found by the commander on a development run; generic description)

A workload mounts a ConfigMap generated by kustomize `configMapGenerator` from a non-YAML source file (an
application config file). The consumer graph has the workload → ConfigMap `references` edge with its mount. It has
**no `reads-file` edge and no unresolved edge** for the paths inside that file.

- `relations/consumers.go` `readsFile` gets the generated data from `g.gen`, finds none, and skips with
  `continue // its data is not in the snapshot`.
- As far as the commander can tell, the generator's source file is not in the environment snapshot. It appears
  only as an evidence excerpt of `kustomization.yaml`.
- The generated object, with its full `data`, is in the rendered manifests (a render artifact).
- **Verify this cause first.** Then report what you found.

## Required

1. **Render fallback.** When a generated ConfigMap's data is not available from the environment snapshot, take it
   from the rendered object of the same side.
   - Match the generator to the rendered object generically: kustomize's name-hash suffix, the namespace, and the
     overlay that renders it.
   - Cite the render artifact and line for every hop.
   - Do not change the environment snapshot or the stored relationship graph. Old bundles and transcripts must still
     replay.
2. **No silent drops.** Whenever a ConfigMap's data is unavailable from every source, record an unresolved
   `reads-file` edge with the reason. `trace_consumers` must report it in `gaps`, and the dossier must too.
   - Check the same for Secrets whose keys are unknown.
   - Check every other `continue` in the consumer-graph builder that hides a reachable relationship.
3. **Tests.**
   - A `configMapGenerator` fixture whose `files:` source is absent from the snapshot and present in the render,
     including the hash-suffixed name: you get the `reads-file` edge with render citations.
   - The same fixture with no render: you get an unresolved edge and a trace gap.
   - Negative controls: a path under another container's mount; an unrelated ConfigMap.
   - Replay of a v9 fixture is unchanged.
4. **No live runs** on the development cases. A live smoke is optional, on a non-development case only.
5. **Update the docs:** `M1-IMPLEMENTATION.md` (known limits) and your status file.

The FLEET.md rules apply, including generic logic only and the files you never open (`GATE-M*.md`, `M*-RESULT.md`).
