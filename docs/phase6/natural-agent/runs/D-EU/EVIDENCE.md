RI's agent request had **no** description (the arm-B `request.json` holds product, versions, environment name, repository and Kubernetes version only), so the natural agent has this orientation text and RI's agent did not.

2. **Release-scope (chart-default) renders.** RI's agent could read renders of each chart version with default values (`list_renders`, scope release). The workspace has only the environment's renders (PROTOCOL §3); the chart's own `values.yaml` for both versions is in `upstream/`.

3. **Diff form.** RI's agent queried a semantic per-object diff with change classes and correlations (`query_diff`, derived); the workspace has a plain `diff -u` of the concatenated renders.

4. **Tools and budgets.** RI's agent: 15 MCP tools over the bundle, 40 turns, 80 tool calls, 600k tokens, 4 MiB of reads, 400 lines per read. Natural agent: Read/Grep/Glob, Bash limited to read-only commands (`ls cat head tail wc find grep diff jq yq`, `kubectl kustomize`; `yq` is not installed on this machine), writes only to `scratch/`, 400k tokens (counted as RI counts them), no turn cap. Neither has network access.

5. **Training knowledge.** Both arms use `claude-sonnet-5-5`, which may know these releases.
