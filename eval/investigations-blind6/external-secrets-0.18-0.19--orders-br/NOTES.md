## Why the two environments differ

Same values file (`installCRDs: true`), stores and consumers. orders-eu declares the Argo CD Application
that installs the add-on (client-side apply). Here the add-on is installed by the platform team's
`platform-addons` ApplicationSet in another repository (README; `input.yaml` `withheld`), so **how the
CRDs are applied is unknown**.

## B1: CRDs too large for client-side apply (decisive) — insufficient-evidence (acceptable: potentially-affected), observed alternatives

Upstream: release v0.19.0 (https://github.com/external-secrets/external-secrets/releases/tag/v0.19.0:
"our CRDs are now too big. Meaning a simple kubectl apply or Argo's default client side apply WILL NOT WORK!
You have to add `--server-side` … ServerSideApply=true") and the getting-started note at the chart tag
(https://github.com/external-secrets/external-secrets/blob/helm-chart-0.19.2/docs/introduction/getting-started.md#L12).

The outcome depends only on the withheld input. Both values were observed with this environment's values
file (kind v0.24.0, kindest/node v1.31.0, Argo CD v3.1.5 from argo-cd chart 8.5.1 default install, the
Application built as an ApplicationSet would generate it; `observed/run.sh … csa|ssa`):
- default sync options (`observed/run-csa.log` L142–L164): sync of 0.19.2 Failed with `metadata.annotations:
  Too long: must have at most 262144 bytes` for both store CRDs; Deployments at v0.19.2, store CRDs still
  0.18.2 — the same outcome as orders-eu.
- `ServerSideApply=true` (`observed/run-ssa.log` L198–L214): sync Succeeded, every CRD at the 0.19.2 schema,
  no last-applied annotation; the probe ExternalSecret syncs.

Hence `insufficient-evidence`: the repository cannot show which applies. `potentially-affected` is also
acceptable (the component is certainly in the change's path and Argo CD's default — the most likely
generator setting absent other information — fails). A clearance (`not-affected`) is wrong; so is
`affected` stated as fact. A correct answer names the missing input: the sync options of the
external-secrets Application generated by `platform-addons` (or whatever applies the add-on).

Render: same as orders-eu (`observed/render.diff`): the two store CRDs grow past the client-side limit.

No security regression (no advisory introduced between v0.18.2 and v0.19.2; GitHub global advisory
database, read 2026-10-27).
